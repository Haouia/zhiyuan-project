# 企业级 RAG 知识引擎 · 演讲提纲

> 用法：先看「一页纸速览」定主线，再按「15 分钟标准版」逐页讲。括号内是建议时长，不是必须。
> 核心原则：**少讲功能，多讲取舍与证据**。评委/领导记不住 13 个服务，但能记住"答案可追溯、效果可度量、权限可管控、运维可观测"。

---

## 一、一页纸速览（讲之前先对自己说三遍）

**一句话定位**
把"能跑通"的 RAG Demo，做成企业"敢用"的知识引擎。

**四条主线（全篇反复回扣）**

| 支柱 | 一句话 | 拿什么证明 |
|---|---|---|
| 可信 | 答案必带引用，引用可回查原文，没依据就拒答 | 引用校验链路 + `INSUFFICIENT_EVIDENCE` 演示 |
| 可度量 | 效果不靠感觉，靠金标评测与质量门禁 | RAGAS 40 题、Faithfulness≥0.90 / Recall≥0.85、趋势图表 |
| 可控 | 租户隔离、角色权限、邀请码注册、限流 | 双租户演示、403/404、邀请码轮换 |
| 可运营 | 模型主备熔断、Token 计量、监控与 traceId | 监控页 10 服务 + 9 指标、用量估算 |

**演讲节奏**：痛点(1) → 架构一条图(2) → 四条支柱(4) → 现场演示(3) → 怎么证明它行(1.5) → 工程化(1.5) → 收尾(1)（15 分钟版）

## 二、15 分钟标准版（推荐）

### 开场：从一个真实场景切入（1.5 分钟）
不要一上来讲技术栈。用一个场景抓注意力：

> "新员工想知道'入职满一年有几天年假'，他要在共享盘里翻 3 份制度文档，问同事也不一定准。
> 我们让通用大模型回答——它不知道公司制度；让它查文档——它可能编一个数字给你。
> 企业知识库真正的问题不是'能不能答'，而是**敢不敢用**。"

痛点四连（每句一句话带过，不展开）：
1. 资料散落，检索靠人肉
2. 通用模型不懂企业制度，容易"一本正经地胡说"
3. 答案没有出处，出错无法追责、无法审计
4. 上线后效果好不好，没有人能给出数字

**承接句**：所以我们做了这个项目——企业级 RAG 知识引擎，重点不在"RAG"，在"企业级"。

### 架构：一张图讲清全链路（2.5 分钟）
> 建议准备一张架构图（接入层 / 身份层 / 业务服务 / 数据层 / 工程层），只讲两条链路，其他快速带过。

**五层结构**（每个一句话）
- 接入层：Vue 控制台（文档库/用量/评测/监控/权限/邀请码）+ 员工问答页 + 自助注册页，统一经网关入口
- 身份与租户：Keycloak OIDC + 密码授权 PKCE，JWT 携带 `tenant_id` 与 `roles`，网关统一鉴权并透传 traceId
- 业务服务：文档服务（解析/版本）、检索服务（BM25+kNN 融合）、AI 服务（生成/限流/主备/计量）、评测服务（Python 离线 RAGAS）
- 数据层：MySQL×2（doc_db/search_db）、OpenSearch、Kafka、Redis
- 工程层：Nacos 服务发现、Prometheus/Grafana、CI 与 K8s

**发布链路（讲一句话 + 强调"绝不半成品上线"）**
上传 → 解析（PARSING）→ Kafka 事件 → 索引写入（INDEXING）→ **核验可搜索分块数** → 才推进生效版本（READY）。
版本有失败态和失败原因，管理员能看到卡在哪一步。

**问答链路（重点，慢慢讲）**
鉴权鉴租 → 两路召回（BM25 关键词 + kNN 向量，RRF 融合）→ 按生效版本二次核验过滤 → 取前 5 个片段 → 模型生成 → **引用校验** → 带编号引用的答案。
一句总结：**每一个环节都有据可查、可解释、可回放。**

### 四条支柱：企业级到底"级"在哪（4 分钟，全场重点）

**1）可信：把"幻觉"关进笼子（1 分钟）**
- 答案是模型基于检索片段生成，编号 `[1]` 与引用列表同序
- 引用必须来自本次召回、且精确匹配对应版本的原文（点开引用能回查"第 x–y 行"）
- 模型输出不合规/引用校验不过 → `502`；资料不足 → `INSUFFICIENT_EVIDENCE`，**宁可不答，也不编**
- 一句话：我们不是让模型"知道"，而是让模型"只能依据证据说"

**2）可度量：效果用数字说话（1 分钟）**
- 40 题金标：30 道有答案 + 10 道资料不足（含负例、含需脱敏样本）
- 门禁：有答案题平均 Faithfulness ≥ 0.90、Context Recall ≥ 0.85
- 离线作业归档报告（发送前脱敏）；管理台可在线运行并查看**趋势折线图、门禁通过率环图、逐题分布散点图、分数直方图**
- 一句话：质量不是"上线后再说"，而是每次都跑分、有门禁

**3）可控：身份、租户、入口都管住（1 分钟）**
- 多租户：tenant-a / tenant-b 数据互不可见，跨租户访问 403/404
- RBAC：ADMIN 管文档/评测/监控/权限，EMPLOYEE 只能问答
- 新成员入口：管理员发邀请码（8 位、每 120 分钟自动轮换、可立即轮换、历史留 10 条）→ 自助注册成为普通成员 → 管理员在「用户与权限」页一键擢升/降级（重新登录生效）
- 一句话：不该看的人看不到，不该有的权限拿不到

**4）可运营：模型也会挂，成本要算清（1 分钟）**
- 模型主备切换（超时/429/5xx 切备一次）、连续失败熔断、冷却后半开探测
- 租户级限流：超额 429 + Retry-After，且不再浪费模型调用
- Token 按租户/日期/模型/用途分项计量，超时未知计费列入"待对账"，界面给估算费用
- 监控页：10 个服务健康+延迟、9 个治理指标（提问量、成功率、P95、Token、切换、Kafka 积压、索引失败）

### 现场演示：按剧本走，每步一句话（3 分钟）
> 演示前必做：`docker compose up -d --wait` 全部 healthy；准备两个浏览器窗口（管理员 / 员工）；准备一份录屏 fallback。

| 步骤 | 操作 | 一句话解说 |
|---|---|---|
| 1 | 打开 `/admin/`，企业单点登录 | "身份和租户由 Keycloak 统一发放，网关只认令牌" |
| 2 | 看文档库 + 打开一篇的版本记录 | "每篇都有版本时间线，能看到解析/索引进度与失败原因" |
| 3 | 进 `/ask/` 问"入职满一年能休几天年假？" | "答案带 [1] 引用，来自这次召回" |
| 4 | 点引用，打开原文高亮 | "引用能精确回查第几行，不是一段模糊的话" |
| 5 | 再问一个资料里没有的问题 | "没有依据时它直接拒答，而不是编一个答案" |
| 6 | 进 RAGAS 评测：看图、点"运行评测" | "报告 +1，趋势/通过率/散点都是真实数据" |
| 7 | 进系统监控 | "10 个服务、9 个治理指标，异常只影响单行" |
| 8 | 邀请码页 → 注册页注册一个成员 → 用户与权限页升为管理员 → 重新登录 | "入职入口是邀请码，权限变更即时生效（重新登录）" |

> 演示是"加分项"不是"风险项"：每步都有讲解词，即使数据为空也能讲清楚"空态为什么这样设计"。

### 怎么证明它行（1.5 分钟）
不要念测试数量堆砌，讲"证明链条"：
- **接口契约**：18 条外部接口 + 9 条内部接口，统一错误信封（code/message/traceId）、角色隔离
- **分阶段验收**：登录/租户隔离 → 上传版本/幂等/失败态 → 双租户问答 → 主备熔断/限流/计量 → 发布门禁
- **API 冒烟**：105 项全绿（含注册/邀请码/升降级 99 项）
- **浏览器 E2E**：26+19+21 项检查、三档分辨率、控制台/网络零错误
- **一键门禁**：`verify_release.ps1` 与 CI 完全一致——"本地能过 = CI 能过"

### 工程化与交付（1.5 分钟）
- **一键起全栈**：13 个容器（网关/4 Java 业务/Python 评测/Keycloak/MySQL/Kafka/OpenSearch/Redis/Nacos/2 模型桩），`docker compose up -d --wait`
- **固定版本交付**：基础镜像 sha256 锁定、每服务不可变 tag、发布清单可回滚
- **K8s 就绪**：三类探针、资源 limits、PDB、`maxUnavailable: 0` 滚动发布
- **可观测**：Prometheus 指标 + Grafana 看板 + traceId 全链路（网关→检索→原文回查→模型）

### 收尾（1 分钟）
> "企业知识引擎的竞争力，不是模型多强，而是让组织敢把知识交给它：
> 每一句答案有出处，每一次迭代有分数，每一个账号有边界，每一个故障有指标。
> 这就是我们从 Demo 走到企业级的四步。"

可扩展方向（挑 1-2 个讲，别全念）：向量端点切换、评测接生产 RAGAS 模型、多模态文档、问答→任务型 Agent。

## 三、5 分钟电梯版（只有一页 PPT 也能讲）

1. **痛点**（40s）：资料散、模型编、无出处、无度量
2. **方案**（60s）：五层架构一条图 + 两条链路（发布/问答）
3. **三个关键词**（120s）：
   - 可信：引用闭环 + 不足拒答
   - 可度量：40 题金标 + 0.90/0.85 门禁 + 趋势图表
   - 可控：双租户隔离、RBAC、邀请码、升降级、限流熔断
4. **证据**（60s）：契约 27 条接口、API 105 项、E2E 66 项、一键门禁
5. **收尾**（20s）："让企业敢把知识交给它"

## 四、30 分钟深度版（技术评审/答辩）

在 15 分钟版基础上插入 4 个"深挖页"，每页 2–3 分钟：

1. **版本一致性难题**：为什么"索引成功≠生效"？跨服务事件 + 分块数核验 + 失败可重放；Kafka 重复投递如何幂等（Idempotency-Key）
2. **检索质量**：BM25 与 kNN 各自适用场景，RRF 融合为什么不用分数加权；租户/版本预过滤如何避免"先污染后过滤"
3. **模型治理**：超时与供应商 429/5xx 的切换边界、熔断参数（2 次失败/冷却/半开）、"待对账"的设计动机（超时无法确认计费）
4. **评测体系**：金标如何构成（有答案/不足/负例）、为什么 10 道不足题不参与 Recall、脱敏为何在归档前做

> 深挖页的讲法：**先抛问题（如果……会怎样？），再讲我们的取舍，最后给证据**。评委想听的是"你为什么这么选"，不是"你用了什么"。

## 五、Q&A 预案（挑最可能被问的 8 个）

| 问题 | 回答要点（15 秒内） |
|---|---|
| 为什么不用现成 RAG 平台？ | 企业要求引用可回查、租户隔离、评测门禁、可运营，这些是平台的黑盒；我们每个环节都可控可审计，且已用契约测试锁定 |
| 怎么控制幻觉？ | 三重约束：检索片段限定 + 引用必须匹配原文 + 无依据直接拒答；效果由金标门禁回归 |
| 数据安全怎么保证？ | 租户数据物理隔离（同一 OpenSearch 按租户+版本过滤，跨租户 404）；模型端点仅内网可控桩，文档不外发；评测归档前脱敏 |
| 效果数字可信吗？ | 40 题金标可复跑，报告归档可追溯；门禁 0.90/0.85 与 CI 一致，每次发布都跑 |
| 成本和性能？ | Token 分项计量 + 估算费用 + 待对账；限流 429 保护；监控页实时看成功率/平均耗时/积压 |
| 出故障怎么办？ | 主备切换 + 熔断 + 半开探测；监控 10 服务；traceId 串联定位；回滚有发布清单 |
| 怎么上线？ | 固定版本镜像 + K8s 配置（探针/资源/PDB/滚动更新）+ 一键门禁，回滚脚本演练过 |
| 最难的点是什么？ | 讲一个真实故事：例如 Keycloak 26.8 不暴露未托管用户属性导致目录为空 → 用租户分组兜底；或"引用校验"要求答案与原文逐字匹配版本——"一致性比功能更难" |

## 七、表达技巧（三个"不要"）

1. **不要念功能清单**：一页 PPT 一个观点，服务名能省就省
2. **不要只讲"做了什么"**：每个模块配一句"为什么这么做/不这么做会怎样"
3. **不要回避数字**：0.90/0.85、105 项、13 个容器、traceId——数字是可信度的来源
